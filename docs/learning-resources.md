# Каталог задач для Recommendations

Маршруты `/v1/internal/resources/*` включаются через `TASKS_RESOURCE_TOKEN`.
Нужен `Authorization: Bearer ...`; пользовательские роли токен не заменяют.
Маршруты не проксируются в публичный API. Токен задается в секретах сервиса.

| Метод | Путь | Параметры и ответ |
| --- | --- | --- |
| GET | `/v1/internal/resources/snapshot` | `limit`, `watermark`, `cursor`; возвращает `watermark`, `resources` и при продолжении `next_cursor` |
| GET | `/v1/internal/resources/changes` | `after` (по умолчанию 0), `limit`, `watermark`; возвращает `watermark`, `changes`, `through`, `more` |
| POST | `/v1/internal/resources/availability` | `{"resources":[{"task_id":"uuid","task_version_id":"uuid"}]}`; возвращает доступное подмножество в том же формате |
| POST | `/v1/internal/resources/diagnostic-eligibility` | Как `availability`, но только для диагностики пользователя из `X-User-ID` |

Страница по умолчанию из 50 строк, максимум 100. Проверка доступности принимает
1-100 пар без дублей, тело до 32 КиБ. На чтение каталога отводится не более 5 секунд.
Для снимка без курсора сервер фиксирует текущую версию. Запрашивай продолжения
с тем же `watermark` и последним `next_cursor`, пока курсор не исчезнет.

После снимка читай журнал с `after`, равным границе снимка. Внутри прохода при
`more: true` передавай прежний `watermark` и `after=through`. После последней
страницы возьми новый watermark, продолжая от прежнего `through`. Записи и
checkpoint на стороне потребителя фиксируются вместе. Повтор чтения той же
границы возвращает те же `event_id`. У журнала пока нет удаления записей по TTL.

Записи снимка и журнала используют один формат: `event_id`, `event_type`,
`schema_version: 1`, `aggregate_id` (ID задачи), `aggregate_version`,
`occurred_at`, `tombstone` и условное `metadata`. В Tasks
`aggregate_version` совпадает с позицией журнала. При `task.resource.updated`
метаданные содержат ID версии, заголовок, тип, сложность, темы с весами,
языки и оценку времени, если она задана. При `task.resource.removed`
`tombstone: true`, `metadata` отсутствует. Это не событие для Feed.

Текущий редактор поддерживает одну тему. Каталог отдает ее как
`topic_weights: [{"topic_id":"uuid","weight":1}]`. У выбора ответа
`languages: []`. Для кода указывается язык с версией из опубликованного
набора тестов. Задача без темы или рабочего способа проверки не входит
в каталог. Условие, варианты ответов и настройки проверки в него не копируются.

Перед показом задачи из каталога или сохраненного плана проверь точную версию
через `availability`. Ресурс исключается, если он больше не опубликован,
версия сменилась или указанный рантайм сейчас не поддерживается в Tasks.
Ответ не гарантирует, что песочница сейчас отвечает.

Для диагностики Recommendations передает UUID из проверенного контекста
пользователя, не из тела входящего запроса. Tasks исключает задачи, которые
этот пользователь создавал, редактировал или пробовал решить, даже если
попытка была по другой версии. Ответ содержит только пары ID и не раскрывает
причины исключения. Проверка опирается на историю в Tasks: она не учитывает,
например, ответы, которые пользователь видел вне платформы.

В административных POST и PUT `estimated_minutes` принимает целое число
от 1 до 1440. Если в PUT поля нет, сохраняется прежняя оценка. Явный `null`
удаляет оценку в новой версии. Для старых задач оценка неизвестна.

Миграция заполняет журнал для опубликованных пригодных задач и устанавливает
триггер на публикацию, смену версии и снятие с публикации в той же транзакции.
Обновление использует общую строку счетчика, чтобы видимый watermark не обогнал
не завершившуюся транзакцию. Перед продакшеном оцени длительность заполнения
на копии каталога: миграция блокирует изменение задач до конца заполнения.
