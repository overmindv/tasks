# Учебные результаты Tasks

Tasks публикует `learning.outcome.v1` после атомарной записи оценки и outbox.
Событие отделено от запусков Sandbox и активности для ленты. Попадают
результаты задач с выбором ответа и оцененные запуски кода. Пробные запуски,
отмена, ошибки проверки и сбои инфраструктуры событие не создают.

Ключ Kafka и `aggregate_id` равны `submission_id`. Outbox хранит стабильный
`event_id`; после подтверждения брокером очищается тело события. Повторная
доставка возможна, потребитель дедуплицирует `event_id`. Для одного решения
потребитель учитывает только наибольшую `correction_version`. Первая оценка
имеет версию 1. Исправления и повторная выгрузка не входят в этот этап.

В событии есть только ID решения, учащегося, задачи, проверенной версии,
темы этой версии, вердикт и время оценки в Tasks. Если у задачи не было темы,
`topic_ids` пуст. Код, варианты ответа, тесты, ссылки и вывод проверок не
передаются. `first_independent_attempt` означает, что до фиксации оценки
у пользователя не было оценки по этой задаче, включая предыдущие версии,
и пользователь не был ее автором или редактором. Признак не подтверждает,
что пользователь не видел ответ вне платформы.

## Включение

Примени миграции перед запуском. Индекс истории создается через
`CREATE INDEX CONCURRENTLY`, без блокировки записи решений на время сборки.
Топик создается заранее. Разреши запись только Tasks, чтение только
Recommendations. Не давай Sandbox, Feed или общей панели читать этот поток.
Используй ограниченное хранение в Kafka.

`TASKS_LEARNING_OUTCOMES_ENABLED` по умолчанию выключен. Включай после
настройки прав и на всех репликах Tasks; выключенные реплики не создают события.
Ранее записанные оценки учитываются при определении первой попытки, но не
публикуются задним числом.

## Проверки

Примени миграции на выделенную БД с именем, оканчивающимся на `_test`, и задай
`COMPONENT_TEST_DSN` с ее адресом.

```sh
go test -race -tags=component -run '^TestLearningOutcome' ./tests/component
go test -tags=component -run '^$' -bench '^BenchmarkLearningOutcomeChoice$' -benchmem ./tests/component
```

Для проверки публикации добавь `OUTCOME_TEST_KAFKA_BROKERS`. Нужны пустая
тестовая БД после миграций и отдельный брокер с заранее созданным
`learning.outcome.v1`. Тест проверяет повтор с тем же ID после потери ack и
очистку тела после подтверждения.
