# OVM-247 — закрытый вывод исполнения

## Результат

Tasks присваивает sample_visible только проверенным открытым примерам.
Legacy/unknown/hidden cases скрыты целиком, даже если test_id похож на open-1.
Безопасная независимая проекция применяется в Get/ListMine и повторно в HTTP DTO:
owner/admin/history/submit replay не публикуют phase output и raw checker failure.
DTO не содержит внутренний marker. Новые failure записываются в безопасном формате.
Kafka mismatch logs содержат координаты, а не недоверенные ID из envelope.

## Evidence

RED→GREEN: HTTP owner/admin/history/direct DTO раскрывали HIDDEN_INPUT в
stdout/stderr/phase/error; теперь скрывают. Дополнительный RED→GREEN на marker
в неверных submission/attempt ID подтвердил утечку в Kafka mismatch log.
Проверены sample feedback, запрет forged marker из sandbox, сохранение raw
source в repository без его публикации, отсутствие мутации исходной записи.

Exit 0: make test (race), go vet ./..., CGO_ENABLED=0 make build, make lint
с GOTOOLCHAIN=go1.26.1, contract checker с sandbox (6 fixtures и negatives).
PostgreSQL17 component tests с race: marker переживает JSONB round-trip,
legacy echo/stderr/error не попадают в owner/admin/history; OVM245/246 regressions.
Нестабильность прежнего ClaimOutbox fixture устранена: ready timestamp задаётся
часами БД, потому что host/Docker clocks различаются. Production queue не изменена.
Независимый review: Important/Critical нет.

## Изменения и ограничения

Новый необязательный внутренний JSONB marker; SQL migration не требуется.
Имена и типы HTTP/GraphQL полей сохранены. Legacy tests без marker теперь скрыты.
Настоящие hidden grading/sample modes остаются OVM-244; проверены synthetic
security fixtures, а не выполнение hidden кода через gojudge.
Raw hidden payload в новый диагностический канал tasks не сохраняется
(retention=0); старые DB записи защищены read projection и не переписываются.
Фактический cleanup диагностического storage sandbox отдельно не аудирован.
Rollback старого tasks бинарника вернёт старое раскрытие и небезопасен.

После коммита — разрешённое пользователем слияние всей цепочки с main.
