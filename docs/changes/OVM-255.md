# OVM-255: надёжное подтверждение результатов

## Brief и решение

Цель: ошибка PostgreSQL на offset N не должна позволять подтверждение N+1.
Задача Jira: https://overmindv.atlassian.net/browse/OVM-255.
Изменяется только tasks; HTTP, события, схемы БД и sandbox не меняются.
Связанный OVM-241 остаётся открытым: исправление относится к порядку доставки
существующего контракта и не определяет новую execution retry policy.

Выбран последовательный retry текущего record с BlockRebalanceOnPoll.
После успешной обработки повторяется только commit. Бюджет обработки и commit
одной записи — 30 секунд, backoff 1–5 секунд, rebalance timeout — 60 секунд.
При исчерпании бюджета Run возвращает ошибку без следующего poll; app закрывает
клиент и освобождает partition. Следующий consumer получает неподтверждённый
результат; inbox обеспечивает идемпотентность при неоднозначном commit.
Сбой после записи в БД и до Kafka commit допускает повторную доставку.
Отмена контекста освобождает rebalance и завершает цикл без нового commit.

Альтернативы: бесконечный retry блокирует rebalance; pause/resume с независимыми
очередями partition требует лишней конкурентной логики. Для текущего consumer
с PollRecords(ctx, 1) выбран ограниченный последовательный retry.

## План и критерии проверки

- [x] Регрессия: ошибка БД на N, затем успех N и N+1; commits строго N, N+1.
- [x] Ошибка commit повторяет commit N без повторного HandleRunResult.
- [x] Истечение бюджета/отмена не допускают poll N+1; rebalance освобождён.
- [x] Повторная доставка после остановки сохраняет N и N+1.
- [x] Ошибки poll и rejected inbox используют безопасный retry.
- [x] Проверки: go test -race ./..., go vet ./..., make lint, make build.
- [x] Независимый review и handoff с фактическими ограничениями.

Проверить отдельно: реальные restart/rebalance Kafka и PostgreSQL outage.
Docker daemon был недоступен на старте; после запуска Docker Desktop проверен отдельный
временный Kafka 4.3.1. Unit fake сам по себе не доказывает поведение брокера.
