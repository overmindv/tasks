# OVM-252 — редакционная проверка публикации

## Контракт

Одобрение кандидата создаёт draft с неизменяемой атрибуцией, без события публикации.
Публикация требует активную canonical topic из публичного API entities; отсутствие
темы и недоступность каталога блокируют переход. Вызов entities выполняется до
транзакции, затем проверяется неизменность версии под блокировкой задачи.

Для programming нужны атрибуция (имя, ID и HTTP(S) URL источника), опубликованный
immutable suite с поддерживаемым runtime и ограниченными ресурсами и accepted
редакционного запуска именно этой версии. Собственная задача указывает автора
как источник и постоянный URL атрибуции. Импорт не доказывает работоспособность.

Редакционный запуск — отдельный run_mode `editorial` в существующей очереди
sandbox, доступный только admin API. Схема sandbox не меняется. Run привязан
к task version, suite, actor и idempotency key; не создаёт learning outcome,
не попадает в пользовательскую историю и недоступен по public GET даже автору.
Проверяется последний запуск версии: queued/failed запрещают публикацию.
Порядок задаётся sequence PostgreSQL при вставке под task lock, а не временем
часов реплики. Старые editorial без sequence требуют повторной проверки.
Изменение любой published-задачи или suite возвращает её в draft;
новая версия требует новой проверки. Старые версии и решения сохраняются.

## План реализации

Исполнение самостоятельно по writing-plans/executing-plans; дополнительные
согласования отменены прямым поручением владельца продукта.

- [x] Режим editorial: домен, миграция, повторное использование outbox/inbox,
  отдельный admin endpoint и запрет доступа через student API.
- [x] Gate публикации: TopicValidator, version CAS, suite/attribution/latest run;
  candidate approve и изменение версии не публикуют непроверенное содержимое.
- [x] Entities HTTP adapter с timeout и ограниченным ответом; wiring и конфигурация.
- [x] Regression tests: отрицательный verdict, отсутствие suite/темы, гонка версии,
  student privilege escalation, отсутствие learning event и утечки source.
- [ ] Проверки unit/race/vet/lint/build и PostgreSQL component; API документация,
  UI подпись одобрения кандидата, независимый review и CI перед merge.

## Совместимость и rollout

Администратор создаёт задачу/одобряет кандидата, публикует suite, затем вызывает
`POST /v1/admin/tasks/{id}/editorial-runs` с JSON `task_version_id`,
`idempotency_key`, `language` и `source_code` (UTF-8, до 256 KiB). Ответ 202
содержит `id` и `status`; polling — `GET /v1/admin/editorial-runs/{id}`
с проверенной ролью admin (ID, версия, status и verdict без исходников/вывода).
Public GET решений отклоняет editorial даже для admin, чтобы не менять
семантику GraphQL DTO. После accepted можно вызвать обычную смену статуса.
Отключение runtime или новый queued/failed запуск запрещают публикацию.
`TASKS_ENTITIES_URL` задаёт внутренний URL публичного каталога; пустой URL
не отключает gate, а возвращает 503. Кэш разрешения публикации не используется.

Сначала миграция, затем все tasks workers/API. Старые workers не поддерживают
editorial: смешанный rollout не допускается. Gateway передаёт ошибки публикации
как прежде; admin tooling вызывает внутренний endpoint. UI одобрения больше
не обещает публикацию. Существующие published версии не снимаются с публикации
миграцией; gate применяется при следующей публикации/обновлении.

## Проверка и продолжение

code-review-graph отсутствует в PATH; анализ зависимостей выполнен rg и чтением
use cases, adapters, consumers и схем. Локально прошли make test (race), lint,
build, go vet и make ctest на выделенной PostgreSQL 17. Sandbox result в component
сценарии подан через handler; реальный sandbox, Kafka и полный стек не запускались.
Независимый review не нашёл блокеров; OpenAPI исправлен. Admin polling отделён
от public API и проверен unit/HTTP access tests. При инфраструктурной ошибке
редактор создаёт новый запуск с новым ключом: существующий replay для draft
не используется. Deployment не выполнялся. Следующий срез — OVM-272.
