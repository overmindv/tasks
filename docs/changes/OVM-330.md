# OVM-330: SQLite-решения через sandbox

## Что изменилось

`tasks` принимает язык `sqlite` и один исходник `solution.sql`. Запрос уходит
в sandbox существующим Kafka-контрактом `sandbox.run.request.v1` без новых полей:
`language.id="sqlite"`, `execution.suite` — ссылка на опубликованный набор,
`execution.inputs` пуст (sandbox читает `sandbox.inputs.v1` из object storage).
Сравнение результата выполняет tasks чекером `sqlite_rows`.

## Совместимость

- SQLite принимается только для версии задания с опубликованным sqlite-suite.
  Режим `samples` (без suite) отклоняется, остальные языки и режимы не меняются.
- Версия рантайма задаётся `CODE_EXECUTION_SQLITE_VERSION` (по умолчанию `3.46`)
  и должна совпадать с registry sandbox (`configs/languages.yaml`).
- Текст запроса ограничен 64 KiB — тем же лимитом, что у адаптера sandbox.
- Для sqlite разрешён только чекер `sqlite_rows`. Набор кейса
  (`{"ordered": bool, "tables": [...]}`) и эталон строк валидируются при
  сохранении и публикации suite: невалидные данные не доходят до sandbox.

## Сравнение и приватность

`sqlite_rows` сравнивает JSON-массивы строк с учётом дублей; порядок проверяется
только при `ordered=true` в наборе кейса. Невалидный эталон даёт `checker_error`,
невалидный вывод sandbox — `wrong_answer`. Наборы данных и эталоны остаются
в tasks; для скрытых кейсов stdout/stderr не возвращаются пользователю.

## Выкладка

1. Sandbox: включить `sqlite` в registry (сейчас `enabled: false`) и задеплоить
   рантайм с адаптером из OVM-313.
2. Tasks: `CODE_EXECUTION_SQLITE_VERSION` должен совпадать с версией sandbox.
3. Gateway: значение enum `ITProgrammingLanguage.sqlite` публикуется артефактом
   схемы; frontend закрепляет новый pin.
